Build Custom AI Workflows with SKILL.md

A practical guide to creating, structuring, and invoking custom skills that teach GitHub Copilot to handle specialized, repeatable tasks.

1 What Are Skills? 2 File Structure 3 Creating a Skill 4 Triggers & Invocation 5 Real Examples 6 Best Practices 7 Troubleshooting Quick Checklist

A Skill is a SKILL.md file that packages domain knowledge, step-by-step instructions, and invocation triggers into a reusable workflow for GitHub Copilot. Instead of re-explaining the same task every session, you write it once in a SKILL.md file — and Copilot automatically recognizes when to use it based on what you ask.

Skills work inside VS Code with GitHub Copilot Chat. They live in a designated skills folder and are loaded into Copilot's context automatically. This guide walks you through everything from creating your first skill to writing production-ready skill files.

Section 1

What Are Skills?

The Core Idea

Skills are instruction files that teach Copilot a specialized workflow. Each skill lives in its own subfolder and contains a SKILL.md file — a markdown document with a YAML header (frontmatter) that tells Copilot when to use it, and a markdown body that tells Copilot how to execute it.

Think of a skill as a standing operating procedure (SOP) baked directly into your AI assistant. Once written, you never have to repeat those instructions again — just ask naturally, and Copilot reads and follows the skill automatically.

What Skills Are Good For

  • Repeatable multi-step workflows — tasks you do weekly or monthly (e.g., pull Instagram metrics, generate a clip guide from an interview)
  • Domain-specific knowledge — context Copilot wouldn't otherwise have (e.g., your team's file naming conventions, VA-specific tools, internal URLs)
  • Tasks with consistent inputs and outputs — skills shine when the process is predictable even if the data changes
  • Automations using external tools — Playwright, ffmpeg, Python scripts, Node.js — skills can instruct Copilot to invoke any tool available on your system

How Skills Differ from Regular Chat

Regular Chat Skills
You re-explain the task every session Instructions are written once and reused forever
Copilot improvises based on general knowledge Copilot follows your exact documented process
Context is lost when the conversation ends Knowledge is persistent — stored in a file
Results vary with prompt phrasing Results are consistent — same process every time

Where Skills Live

Skills are stored in a folder configured in your VS Code settings. At VA, the default location is:

C:\Users\<yourname>\.copilot\skills\
  instagram-metrics\
    SKILL.md
  secva-clip-finder\
    SKILL.md
  secva-quote-clipper\
    SKILL.md

Each skill gets its own subfolder. The subfolder name is just for organization — Copilot reads the SKILL.md file inside it.

Section 2

Skill File Structure

Anatomy of a SKILL.md

Every SKILL.md file has two parts: a YAML frontmatter block at the top (between --- markers), and a markdown body below it.

---  ← frontmatter starts here
name: my-skill-name
description: >
  Describe what this skill does and WHEN Copilot should use it.
  Be explicit about trigger phrases: "Use this skill when the user
  asks to...", "Also trigger when the user mentions..."
argument-hint: 'Optional hint shown to user, e.g. "Which account?"'
---  ← frontmatter ends here

# Skill Title

A short summary of what this skill does.

## Prerequisites
What tools, files, or environment variables must exist before running.

## Step-by-step Instructions
The detailed workflow Copilot should follow.

## Output
What files or results the skill produces.

The Frontmatter Fields

Field Required? Purpose
name Yes Internal identifier for the skill (lowercase, hyphens)
description Yes — most important field Tells Copilot WHEN to invoke this skill. Must include trigger phrases.
argument-hint Optional A short prompt shown to the user asking for any required input
⚠ The description field is the trigger. Copilot uses semantic similarity to match your request against every skill's description. The more specific and natural-language your description is — with real phrases like "Use this skill when someone asks to pull reel views" — the more reliably Copilot will invoke it.

The Markdown Body

After the frontmatter, write the skill as you would any detailed SOP or how-to document. Use headings, bullet lists, code blocks, and tables freely. Copilot reads the entire file as instructions.

Good sections to include in the body:

  • Prerequisites — what must be installed, what files must exist, what credentials are needed
  • Required User Input — questions Copilot should ask the user before starting
  • Step-by-step workflow — numbered steps in the exact order Copilot should follow them
  • Folder & File Structure — where outputs go, naming conventions
  • Output / What This Produces — so the user knows what to expect
  • Edge Cases & Notes — anything that commonly goes wrong or requires special handling
Section 3

Creating Your First Skill

There are two great ways to build a skill — and both let Copilot do the heavy lifting. You don't need to write YAML by hand or manually set up folders. Just describe what you want, or let Copilot learn from what you already did together.

Method 1 Just Tell Copilot What You Want to Automate

The simplest way to create a skill is to describe your goal in plain language and ask Copilot to build the skill files for you. You don't need to know the structure — Copilot handles it.

  1. Open Copilot Chat and describe your workflow

    Tell Copilot what you're trying to accomplish. Be specific about inputs, outputs, tools involved, and how often you do it. Example:

    "I want to create a skill that pulls the weekly Instagram metrics for
@secvetaffairs using Playwright. It should ask me which method I want
(direct links, one week, or one month), then scrape the reels and save
results to a markdown file. Can you build the SKILL.md for this?"
  2. Let Copilot generate the SKILL.md

    Copilot will create the complete skill file — YAML frontmatter, trigger description, prerequisites, step-by-step instructions, and output format — based on what you described. Review it and ask for any adjustments.

  3. Ask Copilot to save it to the right folder

    Tell Copilot to save the file to your skills directory:

    "Save that as SKILL.md inside C:\Users\<yourname>\.copilot\skills\my-skill-name\"

    Copilot will create the folder and file for you.

  4. Test it with a natural trigger phrase

    Start a new chat and ask something that matches your skill's purpose. Copilot should invoke it automatically. If it doesn't, ask Copilot to strengthen the trigger phrases in the description.

Method 2 Do the Work First, Then Turn the Chat Into a Skill

This method is ideal when you've already worked through a complex task with Copilot and want to preserve that exact process as a reusable skill. Copilot reviews the full conversation and distills it into a SKILL.md automatically.

  1. Work through your task in Copilot Chat as normal

    Run the entire workflow — ask questions, iterate, fix issues, refine the output. Don't worry about documenting anything as you go. Just focus on getting the result right.

  2. Once the task is complete, ask Copilot to create a skill from the chat

    At the end of the conversation, say something like:

    "We just worked through this entire workflow together. Can you review
everything we did in this chat and create a SKILL.md file that
captures the full process so we can repeat it automatically in the future?"
  3. Copilot drafts the skill from the conversation history

    Copilot reads through what was done — the tools used, decisions made, files created, errors resolved — and writes a complete SKILL.md that reproduces that workflow. It will include the right trigger phrases, prerequisites, and step-by-step instructions based on what actually worked.

  4. Review, refine, and save

    Read through the generated skill. Ask Copilot to adjust anything that's off — add edge cases you encountered, tweak the output format, or expand the trigger phrases. Then ask Copilot to save it to your skills folder.

✓ Why this method works so well: The skill is built from a process that was already proven to work in your actual environment, with your actual tools and files. There's no guessing — Copilot is codifying something it already did successfully with you.
Section 4

Triggers & Invocation

How Copilot Decides to Use a Skill

When you send a message in Copilot Chat, Copilot compares your message against every available skill's description field using semantic similarity — it's not keyword matching, it's meaning matching. If your message is sufficiently similar to a skill's description, Copilot reads and follows that skill's instructions.

This means your description should:

  • Describe the real-world task in plain language
  • Include explicit "Use this skill when..." and "Also trigger when..." sentences
  • List the actual phrases a user would naturally say
  • Mention specific proper nouns — account names, tool names, product names — that only appear in this context

Writing Effective Trigger Language

Compare these two descriptions for the same skill:

✕ Weak — Too vague

Gathers metrics from social media accounts.

✓ Strong — Specific and trigger-rich

Gather Instagram reel metrics (views, likes, comments, shares) from VA Instagram accounts using Playwright. Use this skill when someone asks to check Instagram metrics, pull reel views, get reel stats, or run a monthly reel report for @secvetaffairs or @deptvetaffairs.

Invocation via Copilot Chat

You don't need a special command or @skill syntax. Just ask naturally in Copilot Chat. Examples that successfully trigger skills:

# triggers instagram-metrics skill
"Can you pull the Instagram metrics for @secvetaffairs this week?"

# triggers secva-clip-finder skill
"I need a clip list from this transcript — find all the quotable moments"

# triggers secva-quote-clipper skill
"Extract clips from this interview video and generate social media captions"
ⓘ Skills are not invoked from the terminal or command palette. They only work through Copilot Chat in VS Code (the chat panel, not inline completions). Open it with Ctrl+Alt+I or click the Copilot icon in the sidebar.

Checking Which Skills Are Loaded

To see all skills currently available to Copilot, ask in chat:

"What skills do you have available?"

Copilot will list all skills it can see along with their descriptions. If a skill is missing from the list, check that the folder path is correct and that the frontmatter is valid YAML.

Minimal Working Example

Here's the smallest valid skill you can write and have working in under 5 minutes:

---
name: weekly-status-report
description: >
  Generate a weekly status report in markdown format. Use this skill when
  the user asks to "write the weekly status", "generate a status report",
  "draft the weekly update", or "create a status summary".
---

# Weekly Status Report Generator

Ask the user for the following before generating the report:
1. What did you accomplish this week?
2. What is blocked or pending?
3. What are your priorities for next week?

Then produce a markdown document with:
- A header with the current date
- Three sections: Accomplishments, Blockers, Next Week Priorities
- Bullet points under each section
- Save as `status-YYYY-MM-DD.md` in the current workspace folder
Section 6

Best Practices

🔍 Write descriptions like a search query

The description is matched against your natural language request. Write it to include the actual phrases you'll use, including synonyms and alternate phrasings.

🎯 Keep each skill focused

One skill = one workflow. Don't combine unrelated tasks into a single SKILL.md. A focused skill is easier to maintain and more reliably invoked.

📄 Document prerequisites explicitly

Always list every tool, file, credential, or environment variable the skill needs. If a prerequisite is missing, Copilot should tell the user rather than silently fail.

🔁 Use consistent output conventions

Define file naming conventions, folder structures, and output formats in the skill. Consistency makes outputs predictable and easier to manage over time.

🤔 Ask before assuming

If the skill needs user input (e.g., date range, account name, file path), add a "Required User Input" section and instruct Copilot to ask before starting.

⚠️ Never hardcode secrets

SKILL.md files may be version-controlled or shared. Never put passwords, API keys, or tokens inside a skill file. Use environment variables or prompt the user to provide them at runtime.

📄 Version your skills

Keep your skills folder in a git repository. This gives you a history of changes and lets you roll back a skill if an update breaks it.

🧰 Test with varied phrasing

After writing a skill, test it with 3–5 different phrasings of the same request. If some don't trigger the skill, add those phrases to the description field.

📚 Write for a new user

Write the skill body as if explaining to a new team member who has never done the task. Include context, rationale, and expected outputs — not just steps.

Section 7

Troubleshooting

Copilot isn't using my skill — it ignores it entirely

Most likely cause: The description doesn't match your phrasing closely enough.

Fix: Open the SKILL.md and add explicit "Use this skill when the user says..." lines with the exact phrasing you used. Save the file and try again.

Also check: The SKILL.md is inside a subfolder of your skills directory — not directly in the skills root. The skills folder path must be correctly configured in VS Code settings.

Copilot says it doesn't see any skills

Fix: Verify the skills folder path in your VS Code settings. Open settings (Ctrl+,), search for copilot skills or check .vscode/settings.json for the skills directory path. The path must point to the folder containing the individual skill subfolders.

Copilot picks the wrong skill

Cause: Two skill descriptions are too similar — Copilot is picking the wrong one based on similarity.

Fix: Make each skill's description more specific. Add language that distinguishes it from the other: "Use this skill (and NOT secva-quote-clipper) when the user wants to find clips from YouTube to record manually with OBS."

Skill is invoked but Copilot doesn't follow the steps

Fix: Restructure the skill body for clarity. Use numbered steps instead of paragraphs. Break complex steps into sub-steps. Add explicit "Before proceeding, ask the user..." instructions where input is needed. The more imperative and explicit the language, the better.

YAML frontmatter errors

Cause: Invalid YAML syntax in the frontmatter block prevents Copilot from reading the skill.

Fix: Ensure the frontmatter opens and closes with --- on its own line. For multi-line descriptions, use the YAML block scalar format (description: >) with the text indented by two spaces. Avoid tabs — use spaces only.

Skill works in chat but not in agent mode

Note: Skills are designed for Copilot Chat. In agent mode, Copilot uses a different tool-selection mechanism. If you need a workflow in agent mode, consider using .instructions.md files or a copilot-instructions.md file in your workspace root instead.

Checklist

Quick Skill Creation Checklist

  • Identified a repeatable workflow worth automating Task you do weekly/monthly with consistent steps and varying data
  • Created a subfolder with the skill name C:\Users\<yourname>\.copilot\skills\my-skill-name\
  • Written YAML frontmatter with name and description Description includes "Use this skill when..." with real trigger phrases
  • Documented prerequisites, steps, and expected output Body is detailed enough that a new user could follow it independently
  • Tested with 3+ natural trigger phrases in Copilot Chat Skill is consistently invoked; results match expected output
  • Skill is live and working! Your workflow is now permanently automated. Copilot will use it every time.
